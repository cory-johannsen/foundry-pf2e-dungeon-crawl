# Themed art for doors and room-feature tokens Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give door, treasure, puzzle and skill-challenge markers custom art that matches the room's theme, chosen by a manifest-driven lookup with safe fallbacks.

**Architecture:** A pure lookup module (`scripts/room-feature-art.mjs`) plus a data manifest (`data/room-feature-art.json`) decides which themed image exists. Room-feature prop tokens take it as their `img`; door walls take it as `animation.texture`. The 32 images are generated by the existing token-art generator (a new subject list in its own prompts module) and keyed to transparency with `tools/make-bg-transparent.mjs`.

**Tech Stack:** Foundry VTT 14 module (ES modules, vitest), Node tools, ComfyUI / OpenRouter image generation, Pillow (via the repo's `.venv`).

**Spec:** `docs/superpowers/specs/2026-10-05-themed-room-feature-art-design.md` (see its "Amendments from planning" section: no corridor door, and the generator is extended with a subject list instead of a new tool).

## Global Constraints

- Module id `pf2e-dungeon-crawl`; assets live under `assets/room-features/<theme>/<kind>.webp`, served as `modules/pf2e-dungeon-crawl/assets/room-features/<theme>/<kind>.webp`.
- Themes (8), exactly the floor-art `locationTag` values: `aberration`, `beast`, `construct`, `dragon`, `elemental`, `fiend`, `plant`, `undead`.
- Kinds (4), the existing room-feature kind keys plus door: `door`, `treasure`, `puzzle`, `skill_challenge`.
- 32 images in total (8 x 4). Transparent-background WebP.
- A missing theme, a missing kind, an unlisted file or a failed manifest fetch is never an error: tokens fall back to the core icon in `ROOM_FEATURE_TOKEN_TYPES`, doors fall back to Foundry's native door (no `animation`).
- A door takes the theme of the room whose wall it is on.
- Only door walls (`door !== CONST.WALL_DOOR_TYPES.NONE`) ever get `animation`.
- No apostrophes inside generator prompt strings; run `node --check` after editing any tool.
- Every merge to `main` bumps `module.json` `version` (patch bump, never reuse a number).
- Variants and open/used/locked state art are out of scope (#764).

## Review Focus

- A room whose `locationTag` is `null` / unknown (older persisted run): markers fall back, nothing throws (Tasks 1, 2, 4).
- `data/room-feature-art.json` cannot be fetched (404, offline, parse error): fallbacks apply, the failure is not cached (Task 1).
- Manifest lists a theme/kind whose file is missing, or a file exists the manifest does not list: the disk-coverage test fails (Task 6).
- A non-door wall passed `art`: it must stay a plain wall with no `animation` (Task 4).
- Hidden-door gate and reveal walls: both get art, from their own rooms' themes; rebuilding a built room never duplicates or changes them (Task 4).
- Re-spawning a room-feature token for an already-built room stays idempotent (flags unchanged, Task 2).

`scripts/room-feature-art.mjs`:

```js
/**
 * Themed art for doors and room-feature prop tokens (#750). Pure lookup over
 * `data/room-feature-art.json` (the manifest of which theme/kind images
 * exist) — no Foundry deps, same pure/data split `creature-art.mjs` keeps.
 * The manifest, not the filesystem, decides what exists: the runtime cannot
 * check files, and a missing entry is always a silent fallback, never an error.
 */
const MODULE_ID = "pf2e-dungeon-crawl";

export const ROOM_FEATURE_ART_THEMES = [
  "aberration", "beast", "construct", "dragon",
  "elemental", "fiend", "plant", "undead",
];
export const ROOM_FEATURE_ART_KINDS = ["door", "treasure", "puzzle", "skill_challenge"];
export const ROOM_FEATURE_ART_DIR = `modules/${MODULE_ID}/assets/room-features`;

/** Module-relative path of the themed image, or null when the manifest does
 * not list that theme/kind (or either name is unknown). */
export function roomFeatureArtPath({ theme, kind, manifest } = {}) {
  if (!ROOM_FEATURE_ART_THEMES.includes(theme)) return null;
  if (!ROOM_FEATURE_ART_KINDS.includes(kind)) return null;
  const kinds = manifest?.[theme];
  if (!Array.isArray(kinds) || !kinds.includes(kind)) return null;
  return `${ROOM_FEATURE_ART_DIR}/${theme}/${kind}.webp`;
}

/** Foundry wall `animation` defaults for a themed door. Task 3's live spike
 * fixes the final values; `texture` is always the themed image. */
export const DOOR_ANIMATION = { type: "swing" };

/** The wall `animation` object for a themed door, or null with no art. */
export function doorAnimationFor(art) {
  return art ? { ...DOOR_ANIMATION, texture: art } : null;
}
```

```js
let ROOM_FEATURE_ART_CACHE = null;

/** Manifest of themed room-feature art (#750). Never rejects: any failure
 * (offline, 404, bad JSON, no fetch) yields `{}` so every marker falls back
 * to its core icon / native door; failures are not cached. */
export async function loadRoomFeatureArt() {
  if (ROOM_FEATURE_ART_CACHE) return ROOM_FEATURE_ART_CACHE;
  try {
    const res = await fetch(`modules/${MODULE_ID}/data/room-feature-art.json`);
    if (!res.ok) return {};
    ROOM_FEATURE_ART_CACHE = await res.json();
    return ROOM_FEATURE_ART_CACHE;
  } catch {
    return {};
  }
}
```
