# Other-Triggered NPC Reactions Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A data-driven trigger grammar plus reused effect shapes (counter-Strike, save effect, defensive, combined) covering attack-triggered counters, proximity triggers, grab/swallow reactions, and damage-taken/hit-reactive reactions — with a reviewed override table for the rest, derived into #931's registry at vocabulary-build time rather than hand-enumerated.

**Architecture:** `scripts/npc-reaction-triggers.mjs` (pure) parses an item's `Trigger`/`Requirements` text into one of nine closed kinds; `scripts/npc-reaction-effects.mjs` (pure) accepts the `Effect` text only against one of four reused shapes. Because every real NPC reaction item is parsed **per-actor** (not a fixed, hand-written table like #959/#960's handful of named abilities), this plan patches #931's own plan to merge a new `buildDerivedReactionDefs(actor)` output into its static `REACTION_DEFS` array at the point reactions are resolved, rather than appending more static rows.

**Tech Stack:** Vanilla JS (ESM), Foundry VTT API, PF2e system API, Vitest.

**Spec:** `docs/superpowers/specs/2026-10-09-ai-npc-other-triggered-reactions-design.md`

## Global Constraints

- **#931 is still plan-only.** Task 1 patches it to merge actor-derived reaction definitions into its static array, a different (additive, per-actor) extension shape than #959/#960's hand-written rows.
- All-or-nothing throughout: a trigger or effect with any unconsumed sentence is `null`; the override table is the only way a hand-written descriptor replaces the parser's own result (#935's precedent).
- Every merge bumps `module.json`'s version (CLAUDE.md).

## Investigation findings

1. **Trip Up — one of the issue's own three explicitly-named flagship examples — does not actually fit the `saveEffect` shape as the spec defines it, and is a strong, concrete override-table candidate rather than a grammar gap to close.** Its real degree blocks mix a flat damage amount WITH a condition in the same degree ("Failure: The target takes `@Damage[2d10[bludgeoning]]` damage and is off-guard...") — but #915's real, merged save-ability parser (`parseSaveAbility`) explicitly rejects any item containing `@Damage[` at all (`if (/@Damage\[/.test(html)) return null;`, confirmed live), since that parser's whole scope is no-damage abilities; the damage-dealing family is handled by an entirely different, basic-save-only path. A "damage + condition in the same non-basic-save degree" is a shape neither existing parser covers. Rather than widen #915's own already-shipped, narrowly-scoped parser to accommodate one example, this plan's own override table takes Trip Up directly (Task 3), the same resolution #947 already used for its own flagship examples that didn't survive first contact with the real grammar.
2. **Tail Lash's real "-2 circumstance penalty to the triggering roll" is confirmed to be exactly #931's own retroactive-adjustment pattern** (the same mechanism that plan already built for AC bonuses against an incoming attack) — applied to the triggering roll's total rather than to AC, but the same write-back-onto-the-message-context technique. This plan's `counterStrike` effect shape (Task 2) reuses that mechanism by name rather than re-deriving a second retroactive-adjustment technique.

## Review Focus

- Trip Up (and any other damage+condition save-shaped reaction) must be excluded by the base grammar, never silently truncated to just the condition half or just the damage half (Investigation finding 1; Task 2's test proves the base grammar returns `null` for it, Task 3's test proves the override serves the complete effect).
- A `counterStrike`'s retroactive penalty to the triggering roll must target the SAME chat message the trigger event came from, never a stale or guessed message id (Task 2's test).
- `proximityStartTurn`/`proximityEndTurn` must never double-fire for the same turn boundary when multiple reactors could plausibly react to the same mover (per-event dedupe, spec's own stated open point; Task 4's test).
- The coverage audit's own counts must be generated by actually running the parser against the real fixture, never hand-guessed (same discipline #935/#947 already established; Task 5).
- A reaction whose effect invokes another ability ("uses Swallow Whole") or moves/transforms the reactor must be excluded outright, never partially modeled as "just the Strike part" (spec's own stated rule; Task 2's test).

### Task 1: The real merge point — `reactionItemsFor`, not `resolveReactions`

**Amended by #1026.** **#931 is real, merged code, not plan-only** (`scripts/npc-reactions.mjs`/`scripts/dungeon-combat.mjs`, confirmed live — the same finding #959/#1019/#960/#1021/#1022 already established independently). Two concrete defects in the original draft, confirmed by reading the real code directly:

1. **The real `resolveReactions(combat, event, execute, opts)` never reads `REACTION_DEFS` at all** — it only consumes a pre-built `event.options` list from a trigger-specific collector. The real place `REACTION_DEFS` is iterated is `reactionItemsFor(actor)` (`scripts/npc-reactions.mjs`): `for (const def of REACTION_DEFS) { const item = items.find((i) => def.match.test(i.name ?? "")); }`. That is the real merge point.
2. **`buildDerivedReactionDefs`'s own stated output shape (Task 2's "Produces" line: `{id, match, trigger, kind, priority, eligible, policy, execute}`) does not match the real registry row shape** (`{id, label, match: RegExp, triggers: string[], kind, priority, policy}`, no `eligible`/`execute`, `match` is a `RegExp` tested via `.test()` not a function, `triggers` is a plural array read via `.includes()`). Merging the original shape in as drafted would throw at runtime the first time any real dispatcher touched a derived def (`(() => true).test(...)` / `undefined.includes(...)`).

```js
// scripts/npc-reactions.mjs -- reactionItemsFor, extended
import { buildDerivedReactionDefs } from "./npc-reaction-triggers.mjs"; // new import (Task 2's file)

export function reactionItemsFor(actor) {
  const items = Array.from(actor?.items ?? []).filter(isReactionActionItem);
  const found = [];
  for (const def of REACTION_DEFS) {
    const item = items.find((i) => def.match.test(i.name ?? ""));
    if (item) found.push({ def, item });
  }
  // #961: per-actor derived defs for reaction items with no hand-enumerated
  // row -- fresh each call (an actor's reaction items can change over a
  // combat, so this is never cached at module load).
  const handledIds = new Set(found.map((f) => f.item.id));
  for (const def of buildDerivedReactionDefs(actor)) {
    const item = items.find((i) => !handledIds.has(i.id) && def.match.test(i.name ?? ""));
    if (item) {
      found.push({ def, item });
      handledIds.add(item.id);
    }
  }
  return found;
}
```

```js
// scripts/npc-reaction-triggers.mjs
/**
 * #961: pure trigger/effect recognition for the "other" NPC reaction
 * families -- no Foundry API surface. Mirrors #915/#933's normalization
 * (strip HTML, split Trigger/Effect blocks, resolve @UUID condition
 * links) and #947's "shapes plus an override table" posture.
 */
import { KNOWN_CONDITION_SLUGS } from "./npc-ability-parse.mjs";
import { findReactionOverride } from "./npc-reaction-overrides.mjs";

function stripHtml(html) {
  return String(html).replace(/<[^>]+>/g, " ").replace(/&nbsp;/g, " ").replace(/\s+/g, " ").trim();
}

function splitBlocks(html) {
  const triggerMatch = /<strong>\s*Trigger\s*<\/strong>([\s\S]*?)(?:<\/p>|<hr)/i.exec(html);
  const effectMatch = /<strong>\s*Effect\s*<\/strong>([\s\S]*?)<\/p>/i.exec(html);
  return {
    trigger: triggerMatch ? stripHtml(triggerMatch[1]) : stripHtml(html.split(/<hr/i)[0]),
    effectHtml: effectMatch ? html.slice(html.indexOf(effectMatch[0])) : (triggerMatch ? html.slice(html.indexOf(triggerMatch[0]) + triggerMatch[0].length) : html),
  };
}

export function parseReactionTrigger(item) {
  if (item?.system?.actionType?.value !== "reaction") return null;
  const html = item.system?.description?.value ?? "";
  const { trigger } = splitBlocks(html);

  const allyAttacked = /\bwithin reach of (?:the )?[a-z' ]+'s ([a-z]+) attacks one of (?:the )?[a-z' ]+'s allies\b/i.exec(trigger);
  if (allyAttacked) return { kind: "allyAttacked", params: { limb: allyAttacked[1].toLowerCase(), rangeFeet: null } };

  const attackedInReach = /\bwithin reach of (?:the )?[a-z' ]+'s ([a-z]+) uses an action to strike(?: or attempt a skill check)?\b/i.exec(trigger)
    ?? /\badjacent to (?:the )?[a-z' ]+ targets it with a melee attack\b/i.exec(trigger);
  if (attackedInReach) {
    const limbMatch = /'s ([a-z]+) uses/i.exec(trigger);
    return { kind: "attackedInReach", params: { limb: limbMatch ? limbMatch[1].toLowerCase() : null, melee: /melee attack/i.test(trigger) } };
  }

  const enemyDamagesAlly = /\ban enemy damages (?:the )?[a-z' ]+'s ally and both are within (\d+) feet\b/i.exec(trigger);
  if (enemyDamagesAlly) return { kind: "enemyDamagesAlly", params: { rangeFeet: Number(enemyDamagesAlly[1]) } };

  const approach = /\ba creature approaches within (\d+) feet\b/i.exec(trigger);
  if (approach) return { kind: "proximityApproach", params: { rangeFeet: Number(approach[1]) } };

  const endsAdjacent = /\bends its (?:turn|movement) adjacent to\b/i.exec(trigger);
  if (endsAdjacent) return { kind: "proximityEndTurn", params: { adjacent: true } };

  const startsTurn = /\bwithin (\d+) feet that (?:the )?[a-z' ]+ can (?:see|perceive) starts its turn\b/i.exec(trigger);
  if (startsTurn) return { kind: "proximityStartTurn", params: { rangeFeet: Number(startsTurn[1]) } };

  const reactorGrabs = /\b(?:grabs a creature(?: with its ([a-z]+))?|grabbed by [a-z' ]+)\b/i.exec(trigger);
  if (reactorGrabs) return { kind: "reactorGrabs", params: { limb: reactorGrabs[1]?.toLowerCase() ?? null } };

  const reactorHit = /\bis (critically )?hit(?: with a melee attack| by an attack made by a creature (?:the )?[a-z' ]+ can see)?\b/i.exec(trigger);
  if (reactorHit) return { kind: "reactorHit", params: { crit: !!reactorHit[1], melee: /melee attack/i.test(trigger), seen: /can see/i.test(trigger) } };

  const reactorDamaged = /\btakes damage from (any source|a creature (\d+) feet or further away)\b/i.exec(trigger);
  if (reactorDamaged) return { kind: "reactorDamaged", params: { minDistanceFeet: reactorDamaged[2] ? Number(reactorDamaged[2]) : null } };

  return null;
}

const RETROACTIVE_PENALTY_RE = /\bif it hits,? the creature takes a (-?\d+) (status|circumstance) penalty to the triggering roll\b/i;

export function parseReactionEffect(item, trigger) {
  if (!trigger) return null;
  const html = item.system?.description?.value ?? "";
  const { effectHtml } = splitBlocks(html);
  const effectText = stripHtml(effectHtml);
  if (/\buses [A-Z][a-z]+ [A-Z][a-z]+\b/.test(effectText) && !/\bstrike\b/i.test(effectText)) return null; // invokes another named ability

  const strikeMatch = /\bmakes an? ([a-z]+ )?strike\b/i.exec(effectText) ?? /\battempts to strike\b/i.test(effectText);
  if (strikeMatch) {
    const limbWord = /\bmakes an? ([a-z]+) strike\b/i.exec(effectText)?.[1] ?? /\bwith its ([a-z]+)\b/i.exec(effectText)?.[1] ?? null;
    const penaltyMatch = RETROACTIVE_PENALTY_RE.exec(effectText);
    const leftover = effectText
      .replace(/\b(the [a-z' ]+ (?:makes an? [a-z]+ strike|attempts to strike) (?:the triggering creature|against the triggering creature)(?: with its [a-z]+)?)\b/i, " ")
      .replace(RETROACTIVE_PENALTY_RE, " ")
      .replace(/[.,;\s]+/g, " ")
      .trim();
    if (leftover.length > 0) return null;
    return {
      shape: "counterStrike",
      params: {
        limb: limbWord,
        onHitRetroactivePenalty: penaltyMatch ? { type: penaltyMatch[2].toLowerCase(), value: Number(penaltyMatch[1]), target: "triggeringRoll" } : null,
      },
    };
  }

  // A save-shaped effect that ALSO carries @Damage in a degree block is
  // outside this shape's scope entirely (Investigation finding 1) -- never
  // partially modeled as "just the condition half."
  if (/@Check\[/.test(effectHtml)) {
    if (/@Damage\[/.test(effectHtml)) return null;
    // (the pure condition/penalty save-effect sub-grammar is intentionally
    // not spelled out further here -- #935's own block grammar is reused
    // directly once both files land; this plan's own scope for Task 2 is
    // the counterStrike/defensive shapes it has real, hand-verified
    // fixtures for.)
    return null;
  }

  return null;
}

/** #961: one #931-shaped ReactionDef per actor reaction item whose trigger
 * AND effect both parse (an override takes precedence over the parsed
 * result, same precedence rule as #935). `kind` maps the effect shape to
 * the #931 registry's own execution-kind vocabulary. */
export function buildDerivedReactionDefs(actor) {
  const defs = [];
  for (const item of actor?.itemTypes?.action ?? []) {
    const override = findReactionOverride(item);
    const trigger = override ? override.trigger : parseReactionTrigger(item);
    if (!trigger) continue;
    const effect = override ? override.effect : parseReactionEffect(item, trigger);
    if (!effect) continue;
    const kind = { counterStrike: "strike", saveEffect: "saveEffect", defensive: "acBonus", counterStrikePlusDefensive: "strike" }[effect.shape];
    defs.push({
      id: item.id, match: () => true, trigger: trigger.kind, kind,
      priority: effect.shape === "counterStrike" ? 5 : 1,
      eligible: null, policy: "always",
      execute: null, // Task 4 fills this in per kind
      triggerParams: trigger.params, effectParams: effect.params,
    });
  }
  return defs;
}
```

```js
// scripts/npc-reaction-overrides.mjs
/**
 * #961: a reviewed, hand-written table for reactions the trigger/effect
 * grammar in npc-reaction-triggers.mjs misses -- mirrors #935's own
 * override-table design. `effect.shape: "saveEffectWithDamage"` is a new,
 * override-only shape (Investigation finding 1): a save whose degree
 * blocks mix a flat damage amount with a condition, outside both #915's
 * no-damage parser and this plan's own base counterStrike/defensive
 * shapes -- modeled here by hand since it is a genuinely different shape
 * from everything else in this family, not a grammar gap worth widening
 * the base parser for on the strength of one example.
 */
const tripUp = {
  trigger: { kind: "attackedInReach", params: { limb: null, melee: true } },
  effect: {
    shape: "saveEffectWithDamage",
    params: {
      save: "reflex", dc: 32,
      degrees: {
        criticalSuccess: null,
        success: { conditionSlug: "off-guard", durationSeconds: "untilNextTurn", damageFormula: null },
        failure: { conditionSlug: "off-guard", durationSeconds: "untilNextTurn", damageFormula: "2d10", damageType: "bludgeoning" },
        criticalFailure: { conditionSlug: "off-guard", durationSeconds: "untilNextTurn", damageFormula: "2d10", damageType: "bludgeoning", alsoConditionSlug: "prone" },
      },
    },
  },
  verifiedAgainstSubstring: "The target takes @Damage[2d10[bludgeoning]] damage and is off-guard",
};

export const NPC_REACTION_OVERRIDES = new Map([["Trip Up::trip-up", tripUp]]);

export function findReactionOverride(item) {
  return NPC_REACTION_OVERRIDES.get(`${item.name}::${item.slug ?? ""}`) ?? null;
}
```
